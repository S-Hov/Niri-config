# Охлаждение Lenovo Legion R9000P ADR10 (83LV)

Этот раздел устанавливает агрессивную программную кривую для **Lenovo Legion
R9000P ADR10 / 83LV** с BIOS семейства **RLCN**. Решение проверено на Arch Linux
с ядром `7.2.3` и использует только штатный драйвер ядра
`lenovo_wmi_other` — без прямого доступа к Embedded Controller.

> [!IMPORTANT]
> Требуется ядро Linux **7.2 или новее**. В `linux-lts 6.18` необходимые
> `fan*_target` отсутствуют, поэтому сервис безопасно завершится, оставив
> управление BIOS.

> [!CAUTION]
> Не устанавливайте для 83LV `LenovoLegionLinux`, не загружайте
> `legion_laptop force=1` и не используйте старые YAML-кривые. На RLCN этот
> драйвер выбирает чужую карту EC `GKCN`, показывает ложные температуры/RPM и
> может выполнить частичную запись.

## Как это работает

Ядро предоставляет три проверенных прошивкой канала:

| Канал | Минимум | Максимум |
| --- | ---: | ---: |
| `fan1_target` | 1600 RPM | 5100 RPM |
| `fan2_target` | 1600 RPM | 5100 RPM |
| `fan4_target` | 1600 RPM | 6500 RPM |

Демон раз в две секунды читает `Tctl` процессора, температуру встроенной AMD
GPU и NVIDIA через `nvidia-smi`. Для управления берётся наибольшая доступная
температура. Значения кривой задаются в процентах собственного диапазона
каждого вентилятора, поэтому пределы прошивки не превышаются.

Повышение оборотов происходит сразу. Снижение сглаживается, чтобы вентиляторы
не меняли скорость при каждом кратком скачке температуры. При остановке,
ошибке, штатной перезагрузке или выключении сервис записывает `0` во все
`fan*_target`, возвращая управление BIOS.

## Проверенная агрессивная кривая

| Температура | Доля диапазона | Fan 1/2 | Fan 4 |
| ---: | ---: | ---: | ---: |
| 40°C | 0% | 1600 RPM | 1600 RPM |
| 50°C | 15% | 2100 RPM | 2300 RPM |
| 60°C | 35% | 2800 RPM | 3300 RPM |
| 70°C | 58% | 3600 RPM | 4400 RPM |
| 80°C | 80% | 4400 RPM | 5500 RPM |
| 88°C | 100% | 5100 RPM | 6500 RPM |

При `90°C` максимум включается независимо от сглаживания. Между точками
используется линейная интерполяция.

В проверочном тесте на 16 из 32 логических потоков вентиляторы достигли
`5100/5100/6500 RPM`; максимальная температура Ryzen 9 8945HX составила
`94.8°C`, после завершения нагрузки температура и обороты штатно снизились.

## Файлы

| Файл | Назначение | Устанавливается в |
| --- | --- | --- |
| `legion-fan-curve.py` | Контроллер температур и RPM | `/usr/local/libexec/` |
| `legion-fan-curve.json` | Кривая и интервалы опроса | `/etc/` |

## Зависимости

```bash
sudo pacman -S --needed linux linux-headers python lm_sensors nvidia-utils
```

`nvidia-utils` нужен для учёта температуры дискретной GPU. Если NVIDIA
выключена или недоступна, контроллер продолжает работать по CPU и AMD GPU.

После установки нового ядра загрузитесь в GRUB через:

```text
Advanced options for Arch Linux -> Arch Linux, with Linux linux
```

Проверка версии:

```bash
uname -r
```

## Установка и миграция

```bash
cd ~/Projects/Arch-full-config
sudo ./cooling/install.sh
```

Установщик:

1. Проверяет DMI `83LV`, ядро 7.2+ и наличие трёх ограниченных WMI-каналов.
2. Останавливает ранее установленный экземпляр контроллера.
3. Отключает старый `legiond` и удаляет несовместимые AUR-пакеты
   `lenovolegionlinux-*`, если они ещё установлены.
4. Архивирует старые конфиги в `/var/backups/legion-fan-curve-*`.
5. На пять секунд задаёт 50% допустимого диапазона и проверяет target/actual.
6. Устанавливает файлы, блокирует ложный `yogafan` и запускает сервис.

Если preflight не проходит, все цели немедленно возвращаются в `0`, а сервис
не устанавливается.

## Управление

Состояние сервиса:

```bash
systemctl status legion-fan-curve.service
```

Температуры, рассчитанные цели и фактические RPM:

```bash
journalctl -u legion-fan-curve.service -f
sensors lenovo_wmi_other-virtual-0
```

Временно вернуть BIOS-auto:

```bash
sudo systemctl stop legion-fan-curve.service
```

Снова включить кривую:

```bash
sudo systemctl start legion-fan-curve.service
```

Отключить или включить автозапуск:

```bash
sudo systemctl disable --now legion-fan-curve.service
sudo systemctl enable --now legion-fan-curve.service
```

## Изменение кривой

```bash
sudoedit /etc/legion-fan-curve.json
python3 -m json.tool /etc/legion-fan-curve.json >/dev/null
sudo systemctl restart legion-fan-curve.service
```

Точка `[70.0, 58.0]` означает 58% между минимальным и максимальным RPM
конкретного вентилятора при 70°C. Температуры должны строго возрастать, проценты
не должны уменьшаться, а последняя точка обязана иметь 100%. Невалидный конфиг
приведёт к остановке сервиса и BIOS-auto.

Основные параметры:

- `poll_seconds` — период чтения датчиков;
- `refresh_seconds` — принудительная повторная запись целей после Fn+Q/прошивки;
- `nvidia_poll_seconds` — период чтения NVIDIA;
- `fall_smoothing` — скорость снижения оборотов;
- `emergency_temperature_c` — температура немедленного максимума.

Не записывайте `fan*_target` вручную при работающем сервисе: он обновит их по
кривой не позднее чем через десять секунд.

## Перезагрузка, сон и Windows

- При обычном выключении или перезагрузке systemd возвращает BIOS-auto, затем
  при следующей загрузке Linux сервис применяет кривую заново.
- После сна процесс продолжает работу и пересчитывает цели в ближайшем цикле.
- В Windows сервис отсутствует: там работают BIOS, Lenovo Vantage или Lenovo
  Legion Toolkit. После возврата в Linux наша кривая применяется снова.
- Для dual boot рекомендуется отключить Windows Fast Startup, чтобы Windows не
  оставляла частично гибернированное состояние оборудования.
- При жёстком отключении питания обработчик завершения не выполняется, однако
  BIOS и WMI-драйвер инициализируют автоматический режим при следующем старте.

## Удаление

```bash
sudo ./cooling/uninstall.sh
```

Скрипт сначала останавливает сервис и возвращает BIOS-auto, затем переносит
установленные файлы в `/var/backups/legion-fan-curve-removed-*`.

## Диагностика

```bash
systemctl is-enabled legion-fan-curve.service
systemctl is-active legion-fan-curve.service
journalctl -u legion-fan-curve.service -b --no-pager
sensors
```

Нормальное состояние: сервис `active`, `fan*_target` ненулевые, actual RPM
постепенно сходятся с target. Если сервис остановлен, target должны быть `0`.
